# Cities Game Mode Design

## Overview

Add a `/cities` route that quizzes players on world cities with 1M+ population. Gameplay follows Map Attack style (3 lives, click to identify) with city-specific features: continent + population filters, dot/boundary rendering toggle, and population display in the HUD.

## Data Pipeline

### Build-time script: `scripts/extract-cities.js`

1. Parse `docs/cities.md` (wiki markup) to extract: city name, country, population, continent
2. Read the GeoJSON from `drei01/geojson-world-cities` (`cities.geojson` — download once, gitignored)
3. Match cities by name; use continent to disambiguate duplicates (e.g., multiple "Moscow")
4. For each matched city:
   - Extract polygon geometry from GeoJSON
   - Compute centroid lat/lon from the polygon (for dot mode)
   - Assign population tier: `>10M`, `10-5M`, `5M-2.5M`, `2.5M-1M`
5. Output `src/lib/data/cities.json` — GeoJSON FeatureCollection
6. Log unmatched cities as warnings for manual review

### Output format (per feature)

```json
{
  "type": "Feature",
  "properties": {
    "name": "Tokyo",
    "country": "Japan",
    "population": 14178000,
    "continent": "Asia",
    "populationTier": ">10M",
    "lat": 35.6762,
    "lon": 139.6503
  },
  "geometry": { "type": "Polygon", "coordinates": [...] }
}
```

## Data Model

### New file: `src/lib/data/cities.ts`

```typescript
type CityContinent = 'North America' | 'South America' | 'Europe' | 'Asia' | 'Africa' | 'Oceania';
type PopulationTier = '>10M' | '10-5M' | '5M-2.5M' | '2.5M-1M';

interface CityProperties {
  name: string;
  country: string;
  population: number;
  continent: CityContinent;
  populationTier: PopulationTier;
  lat: number;
  lon: number;
}
```

Constants:
- `CITY_CONTINENTS`: `['North America', 'South America', 'Europe', 'Asia', 'Africa', 'Oceania']`
- `POPULATION_TIERS`: `['>10M', '10-5M', '5M-2.5M', '2.5M-1M']`
- `POPULATION_TIER_LABELS`: display labels for each tier
- `CONTINENT_COLORS`: color per continent (similar palette to `REGION_COLORS`)
- `getCityList()`: returns all cities with properties

## City Picker UI (Setup Phase)

### Layout: Two filter groups + render toggle

**Continent filter** — 6 toggle chips:
- North America, South America, Europe, Asia, Africa, Oceania
- Each shows count of matching cities (cross-filtered by selected population tiers)
- All selected by default

**Population filter** — 4 toggle chips:
- `>10M`, `10-5M`, `5M-2.5M`, `2.5M-1M`
- Each shows count of matching cities (cross-filtered by selected continents)
- All selected by default

**Render mode toggle:**
- "Boundaries" (polygon) vs "Dots" (circle)
- Default: Dots

**Show country name toggle:**
- On by default
- When off: country name still shown for cities with duplicate names across countries

**Total count:** "42 cities selected" below filters

**Start button:** Disabled when no cities match current filters.

**Persistence:** localStorage key `'cities-game-settings'`

## Gameplay

### Phases: setup → playing → results (same pattern as Map Attack)

### HUD
- Left: City name + formatted population (e.g., "Tokyo 14,178,000"). Country name shown if toggle is on, or if the city name is duplicated in the current game set.
- Center: Progress counter ("12 / 42")
- Right: 3 hearts (lives)

### Map Rendering
- Country borders as light gray reference lines (orientation context)
- Lakes rendered as in other modes
- **Dot mode:** Cities as filled circles (8px radius). Gray when unclaimed, continent color when claimed.
- **Boundary mode:** City polygons with fill + border. Gray when unclaimed, continent color when claimed.
- Hover: brighten unclaimed cities on mouseover

### Click Detection
- Dot mode: 20px radius from city centroid
- Boundary mode: `d3.geoContains()` on polygon + 20px fallback to centroid
- Correct: city fills with continent color, brief green highlight
- Wrong: red flash (500ms), lose 1 life. 0 lives → results. Otherwise re-queue target.

### Zoom/Pan
- Same D3 zoom as MapAttackMap
- Start at world view
- Player zooms/pans freely

## Results Phase

- Dark overlay with centered results card
- Shows: claimed / total cities, win/lose message
- Background map shows claimed cities in continent colors
- Buttons: "Play Again", "Change Cities", "Back to Home"

## Component Architecture

### New files

| File | Purpose |
|------|---------|
| `src/routes/cities/+page.svelte` | Page: 3 phases, city picker, game loop |
| `src/lib/components/CitiesMap.svelte` | Map: D3 zoom, dot/polygon rendering, hover, click |
| `src/lib/data/cities.ts` | Types, constants, city list helpers |
| `src/lib/data/cities.json` | GeoJSON FeatureCollection (generated by script) |
| `scripts/extract-cities.js` | Build-time data pipeline |

### CitiesMap.svelte

Props:
- `targetCity: string` — current target city name (or unique key)
- `claimedCities: Set<string>` — set of claimed city keys
- `renderMode: 'dots' | 'boundaries'` — how to draw cities
- `onCityClick: (cityKey: string) => void` — click handler

Exported methods:
- `flashWrong(cityKey: string)` — red flash on incorrect click
- `redraw()` — force canvas repaint

Renders:
- Country borders (light gray context)
- Lakes
- City dots or polygons
- D3 zoom/pan behavior
- Hover highlighting on unclaimed cities

### Why a new component?

Rendering logic is fundamentally different from MapAttackMap — dots vs polygons, city-level hit detection, no subdivision layer, country borders as context only. Separate component keeps both clean.
